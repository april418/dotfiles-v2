# 根拠と限界

多くの資料は判定ツールやデザイン会社の記事で、測定は少ない。測定と言えるものも、母集団か対照群に限界がある。数字を引くときは限界も一緒に引く。

## AI らしさの測定

| 資料                                                                                               | 内容                                                                                                                                                                                   | 限界                                                                                                                                                                |
| -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Adrian Krebs](https://www.adriankrebs.ch/blog/design-slop/)                                       | Show HN 1,590 件を CSS と DOM の検査で採点した。パターンが 4 つ以上 22%（347 件）、2〜3 つ 32%（508 件）、0〜1 つ 46%（735 件）                                                        | 個人の測定で、母集団は Show HN だけである。誤検出は手動の確認で 5〜10% の見積もりで、分母は書かれていない。記事内で `~1400` と 1,590 が食い違う（内訳の和は 1,590） |
| [SiteBlob](https://siteblob.com/blog/we-scanned-131-ai-built-websites-ai-look-wasnt-the-tell)      | AI 製 131 件と人手 10 件を比べた。見た目の型は 50.4% と 50.0% で差が無い。埋め込みスタイル、信頼要素の不足、セマンティクスと a11y の不足の組み合わせは 82.4%（108 件）と 10.0%（1 件） | スキャナーを売る会社の自社調査である。探索的な監査で対照群が少なく、10.0% は 1 件である。本文も、作者の判定には使えないと断っている                                 |
| [Anthropic](https://claude.com/blog/improving-frontend-design-through-skills)                      | distributional convergence の説明。モデルは学習データの統計的な傾向に沿って予測するので、指示が無いと無難な設計に寄る                                                                  | ベンダーの解説で、測定値は無い                                                                                                                                      |
| [pixelslop](https://cdn.jsdelivr.net/npm/pixelslop@0.3.8/dist/skill/resources/ai-slop-patterns.md) | パターンの検出閾値の例                                                                                                                                                                 | ツールの内部資料で、閾値は作者の経験則である                                                                                                                        |

SiteBlob の結果から読めるのは、見た目の型だけでは人手のサイトと見分けられないことと、作りの欠陥のほうが差が出たらしいことである。対照群が 10 件なので、どちらも手がかりにとどまる。

紫の由来を Tailwind UI のボタン色 `bg-indigo-500` に求める説は仮説である。[Communeify](https://www.communeify.com/en/blog/why-ai-loves-purple-global-design-convergence/) や [DEV の記事](https://dev.to/alanwest/why-every-ai-built-website-looks-the-same-blame-tailwinds-indigo-500-3h2p) のような二次資料が語るだけで、原投稿は確認できておらず、学習データを経由したという因果を検証した研究も見つかっていない。

## 基準

[WCAG 2.2](https://www.w3.org/TR/WCAG22/) の規格である。1.4.3 と 2.4.7 は Level AA、2.2.2 は Level A、2.3.3 は Level AAA で、当てる場面は [readability-check.md](readability-check.md) にある。
