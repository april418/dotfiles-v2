# 日本語固有の点検

英語圏の一覧には出てこない項目である。AI の癖として見出しの句点を測った資料は見つかっていない。この節の見出しの判断は観察に基づくもので、報告にもそう書く。

`page_audit.js` の `headings`、`marks`、`text` を土台にして、折り返しは幅を変えて目で見る。

## 文面

| 点検項目                 | 確かめ方と判断                                                                                                                                                                   |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 見出しの句点             | `headings.kuten` と `headings.list`。情報を探すページの見出しには付けない。絶対の規則ではないので、下の「見出しの句点の扱い」で判断する                                          |
| 読点と句点の二拍の見出し | `headings.twoBeat`。「〜、〜。」の形と対句が機能の見出しに並んでいないかを見る                                                                                                   |
| 見出しの言葉             | 内容の中心を端的に言う。「[公用文作成の考え方](https://www.bunka.go.jp/seisaku/bunkashingikai/kokugo/hokoku/pdf/93731901_01.pdf)」の解説は、飾りの多い言葉遣いを避けるとしている |
| です・ます調と常体の混在 | `marks.desuMasu` と `marks.plainForm`。同じ画面の同じ種類の文で混ざっていないかを読む                                                                                            |
| 記号の混在               | `marks` の `middleDotLatin`（`·`）と `middleDotKana`（`・`）、`spacedSlash`（半角の `/`）、`straightQuotes`（直線引用符）                                                        |

### 見出しの句点の扱い

- 「公用文作成の考え方」に見出しの句点の規定は無い。公用文の解説であって、UI の規定でもない
- 広告コピーでは 1980 年代に句点が現れ、1990 年代に普通になったという読み物がある（[koubo.jp の記事](https://koubo.jp/article/57962)。根拠資料は挙がっていない）。飾りとしての句点には歴史がある
- 見出しに句点を使わないと定めたデザインシステムの例がある（[Photoruction](https://ds.photoruction.com/writing/writing-style)）
- 問題は句点そのものではなく、機能の見出しに一律に当てる均質さである。トップのキャッチコピーの 1 つに付けるのは選択であり、一覧、検索、詳細の見出しの全部に付くのは既定値に見える

## 組版

| 点検項目                           | 確かめ方                                                            | 基準                                                                                                                                                                                                                                                                                                                                                                   |
| ---------------------------------- | ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 語の途中の折り返し                 | 幅を変えて、見出しと説明文が語の途中で切れないかを見る              | 見出しには `word-break: auto-phrase` が使える（[Chrome 119 以降、`lang="ja"` が要る](https://developer.chrome.com/blog/css-i18n-features?hl=ja)）。Firefox は未対応、Safari は preview である（[互換データ](https://raw.githubusercontent.com/mdn/browser-compat-data/main/css/properties/word-break.json)）。未対応のブラウザでは指定が無視され、通常の折り返しになる |
| 和文見出しの負の字間               | `headings.list[].letterSpacingEm` が負である                        | [デジタル庁](https://design.digital.go.jp/dads/foundations/typography/)の字間は 0、1%、2% である                                                                                                                                                                                                                                                                       |
| 1 未満の line-height               | `headings.list[].lineHeight` が 1 未満である                        | [デジタル庁](https://design.digital.go.jp/dads/foundations/typography/)の見出しの行高は 140〜150% である                                                                                                                                                                                                                                                               |
| `palt` を本文全体に当てていないか  | `text.bodyFontFeatures` と `text.palt`（`palt` の当たった要素の数） | `palt` は字を詰める指定で、長い本文では字送りが揃わなくなる。見出しに絞る                                                                                                                                                                                                                                                                                              |
| 本文が意図せず明朝になっていないか | `text.bodyFontFamily` のスタックの順を読む                          | 欧文フォントに和文の字は無いので、和文はスタックの次のフォントで出る。欧文フォントの後ろが明朝なら、本文の和文は全部明朝になる                                                                                                                                                                                                                                         |
| 小さな和文                         | `text.under14`、`text.under12`、`text.atMost10`                     | [デジタル庁](https://design.digital.go.jp/dads/foundations/typography/)は 16px を基準とし、14px 未満を原則として認めていない。14px も付随情報か領域の制約があるときに限る                                                                                                                                                                                              |
| 大文字の英語ラベルと `lang`        | `text.latinCapsLabels` と `text.latinCapsWithoutEnLang`             | 英語のラベルが多いのに `lang="ja"` のままだと、読み上げや折り返しが和文として扱われる。そのラベルに `lang="en"` を付ける                                                                                                                                                                                                                                               |

業務画面の値は資料が割れる。[デジタル庁](https://design.digital.go.jp/dads/foundations/typography/)は情報量を優先する管理画面向けに行高 120%、130% を持ち、個人の OSS のテンプレートは本文 14px、キャプション 12px を初期値としている（[hirokaji の記事](https://note.com/tasty_dunlin998/n/nf1b04ebc7600?hl=en)）。公開サイトの本文と、情報量を優先する業務画面を同じ基準で測らない。
