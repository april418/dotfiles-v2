# 機能と残骸の点検

動かない部品と架空データの残骸は、見た目の好みに関係なく欠陥である。ページごとに `page_audit.js` を流し、ソースがあれば `count_patterns.py` の「残骸の候補」を見てから、下の表を上から確かめる。

状態を変える操作（削除、送信、購入、公開、ログアウト）は本番で押さない。ソースを読むか開発環境で押し、押さなかったものは未確認に書く。

## 操作部

| 点検項目                               | 確かめ方                                                                                                                                     |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 押しても動かないボタン                 | `controls.deadButtons` が React の `onClick` の無いボタンを数える。候補なので、押して何も起きないことを確かめてから欠陥と書く                |
| 親のハンドラに任せているボタン         | `controls.delegatedButtons` は親の `onClick` に渡っているものである。親が別の用途のこともあるので押して確かめる                              |
| `readOnly` の検索欄                    | `controls.readOnlyFields` を見て、文字を打てるかを試す                                                                                       |
| value も onChange も無い `select`      | `controls.deadFields` を見て、選び直して結果が変わるかを試す。`action` も `onSubmit` も無い `form` の中の部品も、ここと `deadButtons` に出る |
| 状態を持つだけで検索に効かない絞り込み | 押して見た目は変わるのに件数が変わらないものである。ソースで、その状態が取得や絞り込みの処理に渡っているかを読む                             |
| 実データと合わない固定の選択肢         | 選択肢を全部押して、件数を表に書く。全件 0 件のものと、どれを押しても件数が変わらないものは欠陥である                                        |
| 「ALL」が一部のデータしか出さない      | 「すべて」の件数と、見出しの統計の件数を並べる                                                                                               |
| 見出しの統計と一覧の件数の食い違い     | 統計の数字を、一覧の実際の件数と API の件数に突き合わせる                                                                                    |

`controls.unjudged` は判定できなかった部品の名前である。水和の途中なら待って流し直す。流し直しても残るものは React の外の部品（クッキーバナー、チャット、静的な部分）なので、手で確かめる。`addEventListener` で動くボタンは `deadButtons` に出るので、押す確認を省かない。`controls.react` が false のサイトは判定できないので、上の条件の範囲で操作部を押して確かめる。

## 残骸

| 点検項目                                         | 確かめ方                                                                                               |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| `href="#"` などの仮のリンク                      | `controls.placeholderLinks` と、ソースの `href="#"`                                                    |
| 固定の件数や更新日                               | 数字と日付の入った文字をソースで探し、実データから出ているかを読む                                     |
| 試作の版表記                                     | 「v 0.2」「HI-FI」のような表記。`count_patterns.py` の「試作の版表記」                                 |
| 架空の例                                         | 説明文の中の例が、実データの形式と合うかを見る                                                         |
| 本物に無い機能の説明                             | 説明文で約束している機能を、実際に操作して確かめる                                                     |
| 内部の記法やテンプレートの変数がそのまま出ている | 本文に `{...}` や `%s` のような文字が無いかを見る                                                      |
| 開発用の調整パネルが本番に出ている               | 本番の URL を開いて、右下や右上の浮いた部品を見る                                                      |
| 雛形のままのファビコン                           | `page.favicons` の URL と公式の雛形の SHA-256 を比べる（下）                                           |
| `description` とページごとの `title` の有無      | `page.description` と `page.title` をページごとに並べる。全ページ同じ `title` は無いのと同じである     |
| 件数が 0 の統計、空の一覧を大きく飾る見出し      | 0 の統計は隠すか、空の状態で次の操作を示す。見出しの級数が空の一覧より大きな面積を取っていないかを測る |

ファビコンは、雛形のファイルと配信中のファイルの SHA-256 を比べる。`page.favicons` が空なら `/favicon.ico` を見る。`data:` の URL は中身を取り出して比べる。`create-vite` の雛形は `packages/create-vite/template-*/public/favicon.svg` にある。古い版の `vite.svg` は `main` に無いので、タグを指定して取る。ほかの雛形も、リポジトリの雛形ディレクトリから同じファイルを取って比べる。

取得とハッシュは別の呼び出しにする。パイプの左に `curl` を置くと、取得に失敗しても終了コードが 0 になり、空の入力のハッシュが出る。保存先はスクラッチパッド（無ければ `mktemp -d` が出したディレクトリ）にし、取得ごとに番号を変える。同じ名前へ取り直すと、失敗したときに前のファイルが残る。

```bash
curl -fsSL -o <保存先>/template-1.svg https://raw.githubusercontent.com/vitejs/vite/main/packages/create-vite/template-react-ts/public/favicon.svg
```

```bash
curl -fsSL -o <保存先>/served-1 <配信中のファビコンの URL>
```

```bash
shasum -a 256 <保存先>/template-1.svg <保存先>/served-1
```

`data:` の URL は curl が扱えない。`,` より後ろを、`;base64` があれば base64、無ければパーセントエンコードとして戻して `<保存先>/served-<番号>` に書き、`shasum` に渡す。

取得のどちらかが 0 以外で終わったら比べず、未確認に書く。雛形は版で変わるので、一致しなくても雛形でないとは言い切れない。一致すれば雛形のままである。
