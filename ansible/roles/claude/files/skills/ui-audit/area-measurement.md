# 表示面積の計測

トップページ以外で、抽象的な文字に面積を使わず、機能と一覧に面積を割けているかを測る。

閲覧時間の 57% は最初の画面に、74% は 2 画面以内に集まるという測定がある（[NN/g、2018 年、120 名、1920×1080 の画面](https://www.nngroup.com/articles/scrolling-and-attention/)）。これは一覧を上に置く根拠であって、何件入れるべきかの基準ではない。閾値は置かず、ページどうしを比べて判断する。

## 測り方

1. PC とスマホの両方の幅で測る。PC は 1280×800 前後、スマホは 390×844 を目安にし、報告に実際の値を書く
2. 幅は `resize_window` で変える。効かないときは `area_audit.js` の `frame` を使い、同一オリジンの iframe で幅を固定する。iframe が読めないとき（`X-Frame-Options` か CSP の `frame-ancestors`）は `error` が返るので、Playwright などで幅を指定する
3. 一覧の 1 件を指すセレクタと、見出し領域の内訳を渡して、ページごとに測る。`navBottom` がサイト共通のナビの下端と違うときは、`chrome` にナビのセレクタを渡す

```js
await uiAuditArea({
  item: '.result-card',
  regions: {h1: 'main h1', lede: '.lede', stats: '.stats', promo: '.featured'},
});
```

| 測るもの                       | 結果のキー                                     |
| ------------------------------ | ---------------------------------------------- |
| 最初の画面に丸ごと入る項目の数 | `list.fullyInFirstScreen`                      |
| 一部だけ見えている項目の数     | `list.partlyInFirstScreen`                     |
| 一覧の先頭の位置               | `list.top`、`list.screensDown`                 |
| 最初の操作部品の位置           | `firstControl.top`（ナビとフッターを除く）     |
| `h1`、説明文、統計、宣伝パネル | `parts`。キーは `regions` に渡した名前         |
| 余白と名前を付けなかった部分   | `gapsAndUnnamed`。横に並ぶ領域は重ねて数えない |
| 一覧と見なさなかった項目       | `list.matched`、`otherItemGroups`、`warnings`  |

## 読み違えやすいところ

- 宣伝パネルを一覧の先頭と取り違えない。パネルの中の項目を先頭と数えると、一覧の位置を実際より上に読む。実測でも起きた誤りである。`area_audit.js` は項目を親ごとに分け（1 件ずつ包まれた項目は、複数の項目を持つ階層まで束ねる）、最も多い親を一覧とし、ほかを `otherItemGroups` に返す。`warnings` が出たら確かめ、宣伝パネルの項目のほうが多いときはセレクタを一覧の中に絞る。日付ごとの節に分かれた一覧は、セレクタを節ごとに渡す
- 説明文を削るだけで足りるかは、内訳で判断する。PC は `h1` の級数と余白と宣伝パネルが大きく、スマホは説明文が最大になることがある。`parts` の大きい順に手を付ける
- CSS の値からの見積もりで済ませない。折り返しと画像の高さは実画面でしか決まらない
- 遅延読み込みで件数が増えるページは、読み込みが落ち着いてから測る

## 判断

トップページはサイトの説明の役割があるので基準として扱う。トップの値を記録し、それ以外のページは機能と一覧を優先する。

| ページ     | 見出し領域に使ってよいもの                         |
| ---------- | -------------------------------------------------- |
| トップ     | サイトの説明。最初の画面の大半を使ってもよい       |
| 一覧、検索 | ページ名と件数と操作部品。説明は短く、一覧を先頭に |
| 詳細       | 対象そのもの。宣伝や再掲を間に置かない             |

補助の内容を全部消す根拠にはならない。EC の中間カテゴリページの研究は、補助コンテンツをサブカテゴリの下に置くか控えめにするよう勧めつつ、モバイルの利用者はそのページに頼ると報告している（[Baymard、2023 年](https://baymard.com/blog/ecommerce-sub-category-pages)）。説明は消す前に、下へ移せないかを考える。
