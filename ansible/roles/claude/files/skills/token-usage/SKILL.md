# token-usage

`scripts/usage.py` は会話記録を読み、リクエストごとのコンテキストの大きさ・キャッシュの読み書き・出力・advisor の呼び出しを
数えて JSON で返す。会話の本文は読まず、`usage` と自動圧縮の記録だけを使う。費用は `PRICES` の定価での換算で、
請求額ではない。

## コマンド

```bash
python3 -B ${CLAUDE_SKILL_DIR}/scripts/usage.py compare --cut 2026-11-20T17:49
python3 -B ${CLAUDE_SKILL_DIR}/scripts/usage.py daily --since 2026-11-01 --cut 2026-11-20T17:49
```

- `compare` は `--cut` の前 `--before-days` 日（既定 7）と、`--cut` から後の全部を比べる
- `daily` は `--since` から日ごとに並べる。`--cut` を渡すと、その日を前後に分ける
- 時刻はタイムゾーンを書かなければ `--tz`（既定 9 = JST）で読む。`--tz` と `--projects` は subcommand より前に書く（`python3 -B ${CLAUDE_SKILL_DIR}/scripts/usage.py --tz 0 compare --cut …`）。後ろに書くと引数のエラーで止まる
- 記録は数 GB になることがあるので、結果はファイルに書いてから読む（`> <scratchpad>/usage.json`）
- パスは引用符で囲まずに、上の形のまま書く。`allowed-tools` の規則が文字どおりに照合するので、`-B` を外したり
  引用符で囲んだりすると許可に当たらない。許可は呼んだターンだけ効くので、後のターンで確認が出たら skill を呼び直す

## 区切りの時刻

区切りは、変更をマージした時刻ではなく、配置先に反映した時刻にする。dotfiles の変更はプレイブックを流すまで
`~/.claude/` に届かない。判断ログに配置の時刻が無ければ、配置先のファイルの更新時刻（`stat`）で確かめる。

`settings.json` の値はセッションを始めたときに読まれるので、反映をまたいで続いたセッションは古い設定のまま動く。
後の期間に古い設定らしいリクエストが残ったら、そのセッションの開始時刻を確かめてから読み方を決める。

## 数え方

| 項目                              | 数え方                                                                                                                                                                               |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| リクエスト                        | `(message.id, requestId)` ごとに 1 件。1 件は複数行に分かれて書かれ、出力が途中までの行もあるので、最後の行を採る。再開や分岐で別のファイルに写された行も、このキーで 1 件にまとまる |
| コンテキストの大きさ（`context`） | advisor 以外の最後の iteration の入力・キャッシュ読み取り・キャッシュ書き込みの和                                                                                                    |
| advisor                           | `usage.iterations` の `advisor_message`。そのモデルの単価で、キャッシュ無しとして換算する                                                                                            |
| subagent                          | `<session>/subagents/*.jsonl` の記録。agent の種類は隣の `.meta.json` の `agentType`                                                                                                 |
| 書き直し（`rewrites`）            | キャッシュに書いた量が 10 万トークン以上かつコンテキストの 8 割以上のリクエスト                                                                                                      |
| 自動圧縮（`compactions`）         | `trigger` が `auto` の `compact_boundary` の記録を `uuid` ごとに 1 件。`pre_tokens_p50` はメインで圧縮する直前のコンテキストの中央値                                                 |

圧縮の要約のリクエストがこの記録に入っているかは確かめていない。

## 読み方

- 1 リクエストあたりの費用は作業の中身でも動く。変更の効き目は、その変更が直接動かす量（コンテキストの分布、
  advisor の呼び出し元、圧縮の回数）で先に見て、費用は `bands`（コンテキストの大きさの区分）ごとの 1 件の費用とあわせて読む
- 後の期間が数日しかなければ、件数とセッション数を数字に添える
- 測っているのはリクエスト単位で、1 つの作業を終えるまでの費用ではない

## 単価の更新

`unknown_models` が空でなければ、そのモデルの費用は 0 として数えている。`PRICES` に足してから流し直す。
単価は記憶で書かず、claude-api skill の料金表で確かめ、`PRICES_AS_OF` をその表の日付にする。

`PRICES` はモデルごとに 1 つの単価しか持たない。プロンプトの長さで単価が変わるモデル（Haiku 5.5 は 10 万トークンを
超えると約 5 倍）は、長いリクエストの費用が少なく出る。
