# 概要

subagent を出すと決めた後に、指示文を書くときと報告を受け取るときの手順である。委譲するかどうかと、
`implementation-validator` に見せる場面は、グローバル指示の「サブエージェント」が決める。

## 指示文

fork 以外の subagent は指示文しか受け取らない。指示は 1 通で完結させ、次を書く。

- 目的とその理由、完了の条件
- 分かっている事実と外れた仮説、既知の落とし穴
- 停止条件（最大回数、前進が止まったら報告）
- 同時に 1 つしか使えないリソース（ポート・ロック・ブランチ）。自分も触らない
- 返す形（結論、根拠のパスやコマンドと終了コード、未確認の点。推測で完了と書かないこと）

渡すものをほかの skill や規則が決めている subagent（ui-audit のレビュー役や `implementation-validator` など）では、そちらに従う。

制約は「〜しない」の規則の形で書く。要約されると、事実は残っても制約が落ちる。

## 報告

- 報告は仮説として受け取り、結論を左右する主張は一次資料で、書き込みの完了はテスト・ビルド・diff で
  確かめてから使う
- subagent が動いている間は、その範囲に触れない作業を進める
- 結果を返さずに終わった subagent の分は自分で引き取る。待ち続けると、成果が空のまま終わる
