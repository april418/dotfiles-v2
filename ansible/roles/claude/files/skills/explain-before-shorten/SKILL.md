# 概要

説明文の組み立てを直す手順である。文の言い回し（主述の対応、比喩、飾り）は
yomiyasu が直すので、ここでは扱わない。yomiyasu より先に通すのは、組み立てを後から
変えると yomiyasu が整えた文が崩れるためである。

考え方は Kazuki Ota さんの記事「[AI の謎な説明文を直すスキル](https://zenn.dev/microsoft/articles/explain-before-shorten)」に
よる。文面はこのリポジトリで書き起こしたもので、記事の SKILL.md とは違う。

## 手順

1. 読み手が読み終えたときに分かっているべきことを、一文で書く。書けなければ、
   直す前に足りない情報を利用者に聞く。要点が決まらないまま短くすると、削る基準が無い
2. その一文を口で説明するとしたら何から話すかを決め、その順に並べ替える。
   結論か、読み手がまず知りたいことから始める
3. 話題が 2 つ以上混ざっている段落は分ける。条件や例外は、それが当てはまる文の
   直前か直後に置く。離れた場所の「ただし」は、読み手がどの文に係るか探すことになる
4. 否定から入る文（「X ではなく Y」「X しないで Y する」）は、Y を先に言う形にする。
   禁止・条件・制約を伝える文は否定形のまま残す。否定が中身そのものだからである
5. 意味を変えずに短くする。削るのは、前の文の言い直し、手順に効かない前置き、
   どの文にも係らない修飾である。説明が足りない箇所は短くせず、言葉を足す
6. 完成した文だけを読み、前の版や会話を知らない読み手に伝わるかを確かめる。
   伝わらなければ 2 に戻る

## 守ること

- 頼まれた範囲だけを直す。範囲の外の文は誤りに気づいても直さずに伝える
- 固有名詞・公式の用語・コード・コマンド・数値は変えない
- 原文に無い事実を足さない。足りない情報は推測で埋めず、何が足りないかを返す
- ファイルを直したときは、保存した結果を読み直し、Markdown の表や箇条書きが
  崩れていないかを確かめる

## 返すもの

直した文章の後に、組み立てを変えた箇所を 1 行ずつ書く（「条件を 3 段落目から
該当の手順の直後へ移した」など）。利用者が本文だけを求めたら、本文だけを返す。
